KI-Verbindung

Nicht verbunden
Gemini kann einen kostenlosen API-Tarif haben, aber mit Kontingent- und Modellgrenzen. Der Schlüssel wird direkt vom Browser an Google gesendet und ist daher weniger geschützt als auf einem Server. Nur einen geeigneten Testschlüssel verwenden.
Wird nicht dauerhaft gespeichert und nicht exportiert. Beim Neuladen neu eingeben. Einen Schlüssel nicht in einem öffentlichen Screenshot teilen.
Voreinstellung laut aktueller Google-Modellübersicht; tatsächlicher Zugriff und kostenloses Kontingent hängen vom Projekt ab.
Sicherer Cloud-Modus: Der Browser ruft Ollama nicht direkt auf. Stattdessen wird ein eigener HTTPS-Worker als Zwischenstelle verwendet; der Ollama-Schlüssel wird dort als Secret gespeichert, nicht in dieser Webseite. Das vermeidet typische direkte Browser-CORS-Probleme und hält den Schlüssel aus dem HTML heraus. Ollamas Gratis-Kontingent bleibt begrenzt.
Diese Adresse erhältst du, wenn du den beigelegten Worker veröffentlichst. Nur die Basisadresse eintragen, nicht /api/chat. Verwende ausschließlich eine HTTPS-Adresse.
Lege einen eigenen langen Zufallscode fest und trage denselben Code als Worker-Secret JARVIS_PROXY_TOKEN ein. Nur während dieser Sitzung im Browser eingeben. Nicht hier im Chat teilen.
Modellname muss für deinen Ollama-Cloud-Zugang verfügbar sein. Verfügbarkeit und Gratis-Kontingent hängen vom Konto ab.

Der Worker braucht zwei Secrets (OLLAMA_API_KEY und JARVIS_PROXY_TOKEN) sowie die Textvariable ALLOWED_ORIGIN mit der exakten HTTPS-Adresse dieser JARVIS-Webseite. Die Anleitung ist in der ZIP-Datei enthalten.

Ollama lokal kostet für die lokale Modellnutzung nichts, benötigt aber einen laufenden Server und ein installiertes Modell. Eine reine Browserseite erzeugt keinen Ollama-Server. Auf Android zeigt 127.0.0.1 auf das Handy, nicht auf deinen Windows-PC. Bei einer HTTPS-Webseite blockiert der Browser oft direkte HTTP-Aufrufe. Für eine sichere Verbindung braucht es später einen erreichbaren HTTPS-Endpunkt mit passender CORS-Konfiguration.
Nur eine erreichbare Server-Basisadresse eintragen, nicht /api/chat. Niemals den Ollama-Port offen ins Internet stellen. Ohne laufenden Server kann der Test nicht erfolgreich sein.
Der Modellname muss exakt mit dem auf dem Server installierten Modell übereinstimmen; hier wird kein Modell automatisch installiert.
